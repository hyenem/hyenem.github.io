02 / 08
단계별 워크플로우 · Request + Return

요청은 오른쪽으로,
응답은 왼쪽으로.

한 번의 트리거가 어떻게 처리되어 답으로 돌아오는지, 그룹과 내부 단계까지 두 장으로 나눠 보여줍니다.

Request 요청 흐름 — Buds 트리거에서 Server 답변 생성까지 버즈가 만든 패킷이 두 경로 중 하나로 서버에 도달, 분기 분석 후 패킷 생성

Return 응답 흐름 — Server 패킷에서 Buds 출력까지 매칭/저장은 갤럭시가, 3rd party 후속과 TTS도 갤럭시가 합성. Others는 단순 통과

Request: 두 경로 모두 마지막 홉은 HTTPS. 갤럭시 = 📱 TLS endpoint(JWT), Others = 🎧 Buds 자신이 TLS endpoint(mTLS E2E). Return: 갤럭시 경로는 폰이 저장·후속·TTS 모두 처리. Others는 서버가 TTS를 직접 만들어 호스트만 통과해 버즈로 직송.

오디오 캡처 & 압축

Ring Buffer

압축 링버퍼

회전 칠판. 새 소리가 들어오면 가장 오래된 소리를 지우고 덮어쓴다. 메모리는 항상 일정.

10 ~ 30 s
Slot

RAM
~165 KB
동시성
SPSC lock-free

Opus 코덱

RFC 6716

오디오용 ZIP. 음악과 음성을 모두 잘 압축. 같은 코덱으로 단일 파이프라인.

구조
SILK + CELT 하이브리드
Bitrate
음성 16k · 음악 32k
Latency
20 ms (low-delay 모드)

~20× 압축
used in Step 1 · 3 · 8

VAD

Voice Activity Detection

"지금 말하는 중?"을 0.01초 단위로 판단. 침묵 0.5초면 자동 종료.

모델
GMM → DNN (compact)
Hop
10 ms
End-of-speech
500 ms 침묵
위치
Buds DSP 온디바이스
used in Step 3 · 자동 종료
왜 압축? Raw PCM 30초 = 2.8MB → 버즈 RAM에 못 들어간다. Opus로 ~150KB. 왜 단일 코덱? 듣던 게 음악인지 말인지 모르니 하나가 둘 다 잘해야 한다 — Opus가 유일한 답.

패킷 / 프로토콜

직전 사운드와 사용자 질문을 한 봉투에 묶어 보낸다 — 확장 가능한 자체 포맷.

used in Step 4 · 6

Session / Frame 2-레이어

BUDS v1.0

큰 봉투(Session) 안에 작은 봉투(Frame) 여러 개. 큰 봉투엔 메타, 작은 봉투엔 실제 오디오 조각.

Header
16 B 고정 (Magic·Ver·Type·SID)
Magic
0x42 0x55 0x44 0x53 ("BUDS")
Frame MTU
240 ~ 1024 B
Integrity
CRC16 (frame) + CRC32 (session)
used in Step 4 · 6

TLV 메타데이터

Type-Length-Value

"이건 뭐(Type)·몇 글자(Length)·값(Value)" 세 칸. 모르는 태그가 와도 길이를 보고 건너뛸 수 있어 무한 확장.

Tag
1 B (256개 슬롯)
Length
2 B (max 64 KB)
이미 정의
DeviceID · TS · Trigger · Codec…
used in Step 4 · 메타 확장

멀티트랙 페이로드

Track A + B

한 패킷 안에 두 동시 트랙. Track A = 직전 사운드, Track B = 사용자 질문. 영상 편집 타임라인처럼.

Track A
Opus 32 kbps · 30 s · ~120 KB
Track B
Opus 16 kbps · 5 s · ~10 KB
총합
~130 KB · ~130 BLE frames
used in Step 4 · 두 트랙 동시 전달
+--------+--------+------------+----------------+----------------+ | Header | Meta | Track A | Track B | Footer (CRC32) | | 16 B | TLV | (직전사운드)| (질문 음성) | 4 B | +--------+--------+------------+----------------+----------------+
왜 자체 포맷? ProtoBuf/MessagePack은 메타 표현은 좋지만 오디오 페이로드용 헤더 효율이 떨어진다. 2-레이어 + TLV는 오디오 스트림 + 확장 가능 메타를 둘 다 잡는다.
