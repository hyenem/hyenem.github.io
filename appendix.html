🎧 카테고리 1 · 오디오 캡처 & 압축

버즈가 사운드를 어떻게 "지금부터 30초 전까지" 가지고 있다가, 필요한 순간에 작게 만들어 보내는가.

🔁 Ring Buffer (링버퍼)

한 줄 : 30초 길이의 회전 칠판. 새 소리가 들어오면 가장 오래된 소리를 지우고 위에 덧씌움. 트리거 순간 칠판을 통째로 사진 찍어 보냄.

비유 : 30초짜리 CCTV 녹화 테이프가 계속 덮어쓰기로 돌고 있다고 생각하면 됨.

🗜️ Opus 코덱

한 줄 : 음악·음성을 작게 압축해주는 "오디오용 ZIP". 30초 오디오를 약 150KB로 줄여 BT로 빠르게 보낼 수 있게 함.

비유 : 30분짜리 영화를 USB에 담으려고 MP4로 압축하는 것과 비슷한데, Opus는 음악과 말 둘 다 잘 됨.

🎙️ VAD (음성 활동 감지)

한 줄 : "지금 사람이 말하고 있나?"를 0.01초 단위로 판단하는 작은 두뇌. 침묵 0.5초가 지나면 "말 끝났네" 하고 녹음을 자동 종료.

비유 : 자동문 센서가 사람이 지나가는 걸 감지하듯, VAD는 "목소리가 지나가는지"를 감지함.

📡 카테고리 2 · 무선 통신 & 네트워킹

버즈가 어떻게 폰뿐 아니라 노트북·TV·차량을 거쳐 인터넷에 연결되는가.

📶 Bluetooth PAN

한 줄 : 블루투스를 "Wi-Fi처럼" 쓰는 모드. 기기끼리 IP 주소를 주고받아 인터넷을 공유함. 모든 OS에 이미 깔려 있어 앱 설치 0.

비유 : 폰의 핫스팟이 Wi-Fi로 인터넷 공유하는 거라면, PAN은 블루투스로 같은 일을 하는 것.

🌉 BNEP

한 줄 : 블루투스 위에 인터넷(이더넷) 패킷을 실어 보내는 "포장지". PAN이 동작하게 만드는 안쪽 메커니즘.

비유 : 컨테이너선이 자동차를 싣고 바다를 건너는 것 — 컨테이너(BNEP) 안에 자동차(IP 패킷)가 들어있음.

🌐 TCP/IP · DNS · DHCP

한 줄 : 인터넷을 동작하게 만드는 3대장. 주소 받기(DHCP) → 이름 찾기(DNS) → 신뢰성 있게 보내기(TCP/IP).

비유 : 호텔 체크인(DHCP) → 전화번호부 찾기(DNS) → 등기우편 보내기(TCP).

🔐 카테고리 3 · 보안

버즈에서 서버까지 가는 동안 호스트(폰·노트북 등)가 페이로드를 못 보게 막는 방법.

🔒 mTLS (Mutual TLS)

한 줄 : 일반 https가 "은행만 신분증 보여주는" 거라면, mTLS는 "은행과 손님이 서로 신분증을 보여주는" 양방향 인증.

비유 : 입국 심사 때 직원이 여권을 확인하면서 나도 직원증을 확인하는 것.

🪪 Secure Element

한 줄 : 버즈 안에 박힌 "금고 칩". 디바이스 비밀키가 여기에만 보관되고, 절대 밖으로 나오지 않음.

비유 : 신용카드 IC칩이나 폰의 지문 인증 칩과 같은 원리. 칩을 뜯어도 키가 안 나옴.

🎫 JWT

한 줄 : "이 사람이 누군지" 적힌 위변조 불가능한 도장 찍힌 종이. mTLS와 함께 이중 인증으로 사용.

비유 : 콘서트 손목띠 — 입장 후에도 화장실 갔다 올 때 손목띠만 보여주면 됨.

🔐 E2E 암호화 (종단간 암호화)

한 줄 : 버즈에서 서버까지 가는 길에 있는 누구도(폰조차도) 내용을 못 봄. 양 끝의 두 명만 풀 수 있음.

비유 : 카카오톡 비밀채팅처럼, 중간 서버도 못 보고 받는 사람만 풀 수 있는 자물쇠 편지.

📦 카테고리 4 · 패킷 / 프로토콜

"직전 사운드 + 음성 질문" 두 트랙을 하나의 메시지로 묶어 보내는 자체 포맷.

📑 Session Message · Frame 2-레이어

한 줄 : 큰 봉투(Session) 안에 작은 봉투(Frame) 여러 개가 들어있는 구조. 큰 봉투엔 "누가/언제/뭐 묶음", 작은 봉투엔 실제 오디오 조각.

비유 : 택배 박스(Session) 안에 부풀림완충재로 감싼 개별 물건(Frame)들.

🏷️ TLV (Type-Length-Value)

한 줄 : 메타데이터를 적는 표준 양식. "이건 뭐(Type) · 몇 글자(Length) · 값(Value)" 세 칸으로 적음. 모르는 항목이 와도 길이를 보고 건너뛸 수 있음.

비유 : 택배 송장의 "품명/수량/내용" 칸이 항상 같은 위치에 있어, 모르는 품명이 와도 무시하고 다음으로 넘어갈 수 있는 것.

🎬 멀티트랙 패킷

한 줄 : Track A(직전 사운드)와 Track B(질문 음성)를 동시에 담는 영상 편집 타임라인 같은 구조.

비유 : 영화 편집 SW의 영상 트랙 + 음성 트랙 + 자막 트랙처럼, 한 묶음 안에 여러 동시 흐름.

🤖 카테고리 5 · AI 처리

서버가 두 트랙을 어떻게 분석해 "정확한 답"을 만들어내는가.

📝 STT (Speech-to-Text)

한 줄 : 사람 목소리(웨이브)를 글자(텍스트)로 받아쓰기 해주는 AI. "방금 뭐였지" → "방금 뭐였지".

비유 : 회의 속기사가 사람들 말을 받아 적는 것의 AI 버전.

🎯 의도 분류 (Intent Classification)

한 줄 : 받아쓴 텍스트가 "어떤 종류의 질문인지" 분류하는 AI. "이 노래 뭐야?" → 음악 식별 의도.

비유 : 우체국 분류 기계가 편지 주소를 보고 "서울행", "부산행"으로 나누는 것.

🎵 Audio Fingerprinting

한 줄 : 음악의 "지문"을 추출해 데이터베이스와 비교하는 방식. Shazam이 같은 기술을 씀.

비유 : 사람 지문이 모두 다르듯, 음악도 1초 안에 고유 패턴이 있고 그걸 비교해 곡을 알아냄.

🗣️ TTS (Text-to-Speech)

한 줄 : 글자를 사람 목소리로 읽어주는 AI. STT의 정반대.

비유 : 책 읽어주는 사람을 컴퓨터가 대신하는 것. 요즘은 진짜 사람 목소리와 구별이 안 될 정도.

🧠 LLM (대형언어모델)

한 줄 : ChatGPT 같은 거대 AI. 의도 분류부터 요약·번역·자유 답변까지 다 할 수 있는 만능 텍스트 두뇌.

비유 : "모든 책을 다 읽은 도서관 사서"가 질문에 답해주는 셈.
