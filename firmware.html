1. 모듈 구성도

  • App Core: 상태 머신, 프로토콜, BT 스택

2. 상태 머신

  • 어떤 상태에서도 CANCEL 제스처(예: 더블탭) → IDLE 복귀
  • 오류 발생 시 → ERROR → IDLE (3초 후)

3. 링버퍼 설계 (가장 중요)

3.1 메모리 제약 분석

옵션30초 @ 48kHz 16bit monoRAMCPU
생 PCM2.88 MB과다거의 0
Opus 압축 (32kbps)120 KBOK~5% DSP
하이브리드200 KBOK~5% DSP

결론: 연속 Opus 인코딩 + 압축 링버퍼로 운영.

3.2 이중 링버퍼 구조

[PCM 스트리밍 출력] │ ├──────────────────────────► I2S → 사용자 귀 (메인 경로) │ ▼ ┌─────────────────────┐ │ PCM Mini-Buffer │ (작은 버퍼, ~500ms) │ 10ms 프레임 큐 │ → Opus 인코더에 공급 └─────────┬───────────┘ ▼ ┌─────────────────────────────────────────┐ │ Opus Encoded Ring Buffer (~150KB) │ │ ┌───┬───┬───┬───┬───┬───┬─────────┐ │ │ │ F0│ F1│ F2│ F3│ F4│...│ ... │ │ │ └───┴───┴───┴───┴───┴───┴─────────┘ │ │ └──── 가장 오래된 프레임 덮어쓰기 ─────┘│ └─────────────────────────────────────────┘ │ │ 트리거 발생 시 ▼ [TrackA 추출]

3.3 프레임 인덱스 테이블

Opus는 가변 비트레이트이므로 프레임 경계를 별도 인덱스로 추적.

typedef struct {
    uint32_t offset;        // 링버퍼 내 바이트 오프셋
    uint16_t length;        // 프레임 바이트 수
    uint32_t timestamp_ms;  // 인코딩 시각
} OpusFrameIndex;

#define MAX_FRAMES 1500     // 30초 @ 20ms 프레임 = 1500개
OpusFrameIndex frame_idx[MAX_FRAMES];
uint16_t idx_head, idx_tail;  // 원형 큐

3.4 동적 길이 조절

  • 사용자가 30초만 필요할 때 60초 보관 중이면 30초만 추출
  • 메타데이터의 TrackA_Duration에 맞춰 head에서 역방향으로 프레임 수집

4. 트리거 핸들링

4.1 터치 입력 처리

// 인터럽트 핸들러 (터치 IC → MCU GPIO IRQ)
ISR(touch_event) {
    uint32_t now = get_ms();
    touch_event_t evt = {now, touch_state()};
    queue_push(&touch_queue, &evt);
}

// 메인 루프에서 패턴 매칭
void touch_pattern_task() {
    if (detect_long_press(2000ms)) {
        if (state == BUFFERING) {
            transition_to(ARMED);
        }
    }
}

4.2 ARMED 단계

  • 짧은 "띵" 효과음(미리 ROM에 PCM으로 저장, ~150 ms) 재생
  • 동시에 마이크 워밍업 시작 (전원/PLL 안정화 ~50 ms)
  • 효과음 끝나는 시점에 RECORDING 진입

5. 마이크 캡처 (Track B)

5.1 캡처 파이프라인

[PDM Mic] → [PDM-to-PCM Filter] → [Noise Reduction] → [VAD] → [Opus Enc] → [Track B Buffer] │ └─► 침묵 800ms 감지 시 종료
  • 샘플링: 16kHz, 16bit mono (STT 표준)
  • VAD: 에너지+ZCR 기반 또는 WebRTC VAD
  • 최대 녹음 시간: 8초 (안전 상한, 무한 녹음 방지)
  • 최소 녹음 시간: 500 ms (오트리거 방지)

5.2 종료 조건

  • VAD 침묵 800 ms → 자연 종료
  • 최대 8초 도달 → 강제 종료
  • 사용자 재트리거(취소) → 폐기

6. 인코딩 & 패킷 빌드

ENCODING 진입 │ ├─► TrackA 추출: │ - frame_idx 역추적으로 30초 분량 시작점 찾기 │ - 해당 구간을 새 버퍼에 연속 복사 (또는 zero-copy 참조) │ ├─► TrackB 인코딩: │ - 녹음 종료 후 한 번에 Opus 인코딩 (보통 100~200ms) │ ├─► 패킷 빌더 호출: │ build_session_message( │ session_id = rand32(), │ trigger_type = LONG_PRESS, │ trackA_ptr, trackA_len, │ trackB_ptr, trackB_len, │ metadata_tags... │ ) │ └─► Session Message 완성 → TRANSMITTING 진입

Zero-Copy 최적화

  • 링버퍼는 그대로 두고, 시작/끝 포인터만 transmit task에 전달
  • 전송 중 덮어쓰기 방지: lock 또는 "frozen 영역" 플래그

7. BT 전송 (L2CAP CoC)

7.1 분할 전송 루프

void transmit_task() {
    uint16_t total_frames = ceil(msg_size / FRAME_PAYLOAD_SIZE);

    for (uint16_t seq = 0; seq < total_frames; seq++) {
        Frame f;
        f.sof = 0xA5;
        f.seq = seq;
        f.total = total_frames;
        f.flags = (seq == total_frames - 1) ? FLAG_LAST : 0;
        memcpy(f.payload, msg_ptr + seq * PAYLOAD, len);
        f.crc16 = compute_crc16(&f);

        l2cap_send(channel, &f, frame_size);

        // BT 스택 흐름 제어 (credit-based)
        wait_for_credit();
    }

    transition_to(WAIT_RESP);
}

7.2 흐름 제어

  • L2CAP CoC의 credit-based flow control 사용
  • 호스트가 처리 가능한 만큼만 credit 발급 → 버즈 송신 속도 자동 조절

7.3 재전송

  • 폰 NAK 수신 → 해당 seq 프레임만 재전송
  • 3회 실패 → 세션 폐기, 에러음 재생

8. 응답 수신 & 재생

WAIT_RESPONSE │ ├─► 응답 프레임 수신, 재조립 ├─► CRC 검증 ├─► Header.MsgType == 0x02 확인 │ ▼ PLAY_RESPONSE │ ├─► Metadata에서 TTS_Codec, TTS_Offset, TTS_Length 파싱 ├─► Opus 디코더 초기화 ├─► 스트리밍 디코딩 → I2S 출력 │ (받으면서 동시에 재생, 전체 수신 대기 X) │ └─► 재생 완료 → IDLE 또는 BUFFERING 복귀

스트리밍 디코딩

  • 응답 첫 프레임 도착 → 즉시 디코딩 시작
  • 지터 버퍼 ~200ms로 끊김 방지
  • "음... 이 노래는..." 같은 응답이 1초 안에 사용자 귀에 들리도록

9.2 최적화 포인트

  • IDLE 시: 링버퍼 인코딩 중단 (재생이 없으므로)
  • BUFFERING 시: 인코딩만 돌리고 App Core는 깊은 슬립
  • 트리거는 GPIO 인터럽트로 즉시 깨움

11. 의사코드: 트리거 → 전송 한 사이클

void on_long_press_detected() {
    if (current_state != BUFFERING) return;

    // 1. 링버퍼 freeze (덮어쓰기 방지)
    ringbuf_freeze();

    // 2. ARMED 효과음
    play_chime(CHIME_ARMED);
    transition(ARMED);

    // 3. 효과음 끝나면 RECORDING
    while (!chime_done()) yield();

    mic_enable();
    transition(RECORDING);

    // 4. 마이크 캡처 + VAD
    uint8_t mic_pcm[MIC_BUFFER];
    size_t mic_len = capture_until_silence(mic_pcm, 8000ms, 800ms);
    mic_disable();

    if (mic_len < MIN_VOICE_LEN) {
        play_chime(CHIME_CANCEL);
        ringbuf_unfreeze();
        transition(BUFFERING);
        return;
    }

    // 5. 인코딩
    transition(ENCODING);
    uint8_t trackB[OPUS_MAX];
    size_t trackB_len = opus_encode(mic_pcm, mic_len, trackB);

    OpusFrameRef trackA = ringbuf_extract_last(30000ms);

    // 6. 패킷 빌드
    SessionMsg* msg = build_session_message(
        gen_session_id(),
        TRIGGER_LONG_PRESS,
        &trackA, &trackB
    );

    // 7. 전송
    transition(TRANSMITTING);
    int rc = bt_send_session(msg);
    if (rc != OK) {
        play_chime(CHIME_ERROR);
        cleanup_and_return(IDLE);
        return;
    }

    // 8. 응답 대기
    transition(WAIT_RESPONSE);
    SessionMsg* resp = bt_recv_response(10000ms);
    if (!resp) {
        play_chime(CHIME_TIMEOUT);
        cleanup_and_return(IDLE);
        return;
    }

    // 9. TTS 재생
    transition(PLAY_RESPONSE);
    play_opus_stream(resp->tts_payload, resp->tts_len);

    ringbuf_unfreeze();
    transition(BUFFERING);
}

설계 결론 종단간 3초 목표는 모든 단계 합산으로 달성 가능. 가장 가변적인 구간은 서버 AI 처리(200 ms~1.5 s)이며, 핸들러 종류에 따라 사용자 체감 답변 시간이 달라집니다. 스트리밍 TTS 덕에 "답변 끝까지"가 아닌 "답변 시작까지"가 기준이라는 점이 핵심.
