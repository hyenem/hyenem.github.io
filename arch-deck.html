S01 · 버즈 내부

버즈 안에서는 무슨 일이 벌어질까?

사용자는 아무것도 안 하지만 버즈의 기억은 한순간도 안 멈춘다 — 늘 '최근 30초'를 쥐고, 물으면 녹음·포장·전송하고 답을 재생한다.

🔁 늘 기억하기 — 상시 버퍼링

켜져 있는 동안 늘 귀를 열어둔다. 지금 들어오는 소리를 항상 '최근 30초'만큼 기억 — 오래된 건 지우고 새 걸로 덮어쓰며 "방금 30초"를 손에 쥔다.

  • 🔊 내부(이어폰 출력) → 링버퍼 A-int
  • 🎙️ 외부(주변음, ANC〔Active Noise Cancellation, 능동 소음 제어〕 마이크) → 링버퍼 A-ext
헛일 안 하기 — 내부음 처리 분기 (LC3 = Low Complexity Communication Codec)
🔊 내부 소리(이어폰 출력)
이미 LC3 (= LE Audio〔Low Energy Audio〕)?▶그대로 보관 · 재압축 0 ✅
아니면 (A2DP·아날로그)▶PCM → LC3 압축

핵심 수치

링버퍼 30초 · 발화 500ms~8초 · 침묵 800ms 종료

1IDLE 대기겉으론 쉬는 듯하지만 '기억하기'는 계속 돌아간다.
2트리거버튼을 길게 누름(롱프레스 2초) = "지금부터 들을게" 신호.
3ARMED 🔔"띵"(150ms) 소리로 준비됐다고 알림. 이제 말하면 됨.
4RECORDING 🗣️내가 질문을 말하기 시작하면 그 말(Track B)을 담기 시작.
5VAD 종료발화 끝(VAD, Voice Activity Detection)을 잡아 자동 종료(침묵 800ms). 시끄러워도 정확.
6PACKAGING 📦듣던 소리(내부)+주변(외부)+질문을 한 봉투에 + "BudsAI한테 물어봐 줘" 쪽지(SBAP, Samsung BudsAI Protocol).

8WAIT ⏳서버가 처리하는 동안 응답을 기다림.
9PLAY 🔊 → IDLE서버 답(TTS, Text-to-Speech 음성)을 받아 귀에 들려주고 → 다시 IDLE. ('기억하기'는 계속)

S02 · 주변 소리

녹음도 안 하는데 주변 소리를 듣는다고? — ANC

소음을 지우려면 먼저 그 소음을 들어야 한다(ANC) — 버즈는 어차피 늘 듣고 있고, BudsAI는 그 소리를 새로 녹음하지 않고 빌릴 뿐.

1 ANC(노이즈 캔슬링)가 뭐냐 — "반대 소리로 지운다"

소리는 공기의 출렁임(파동). 거기에 정확히 반대로 출렁이는 소리(역위상)를 더하면, 두 파동이 서로 상쇄돼 조용해진다. (마루 + 골 = 0)

3 그래서 '주변 소리'는 공짜로 이미 있다

  • 그 소리(A-ext)를 BudsAI 컨텍스트로 쓰는 건 추가 마이크·추가 전력 없이 — 이미 듣던 걸 활용하는 것.
  • 이어폰 출력(내부음)도 늘 있으니 → 내부 + 외부 둘 다 이미 손안에. (다음 장부터 이 소리들을 줄이고 묶어 보낸다)
ANC = Active Noise Cancellation · 피드포워드(바깥 마이크) + 피드백(안쪽 마이크) · 역위상(anti-phase)으로 상쇄

S03 · 코덱

이 작은 버즈에 30초를 어떻게 담지? — LC3

귀에 스치는 소리도 숫자로는 거대하다 — 6MB짜리 원본을, 칩에 이미 있는 LC3가 '들리는 것만' 남겨 200KB로 줄인다.

1 PCM이 뭐냐 — 소리의 '원본 숫자'

PCM = Pulse Code Modulation(펄스 부호 변조). 소리(공기의 떨림)를 1초에 수만 번 '찰칵' 찍어, 그 순간의 세기를 숫자로 적은 것 — 압축이 전혀 안 된 원본 디지털 소리.

🎙️ 외부(마이크)▶ADC(아날로그→디지털)▶PCM
🔊 내부(이어폰 출력)▶decomp 압축 풀기▶PCM
  • 48kHz = 1초에 숫자 4만 8천 개 (각 숫자 = 진동판 위치, 16bit −32768~32767)
  • 48kHz·16bit·mono = 1초당 96KB → 30초 한 채널 2.88MB
  • 구조도 압축도 없어 그냥 크다 → 그대로는 못 보냄

2 압축하면 얼마나 작아지나 한 요청 · 전부 LC3 24kbps

생 PCM (원본)≈ 6 MB
블루투스로 보내면 40초+ → 제품 불가
LC3 24kbps≈ 200 KB
약 1/30 크기 · ~2초 전송
생 PCMLC3 24kbps
내부(이어폰) 30초2.88 MB~90 KB
외부(주변음) 30초2.88 MB~90 KB
발화 5초0.16 MB~15 KB
한 요청 합계~6 MB~200 KB

3 왜 여러 코덱 중 LC3?

  • 버즈4 프로 지원 SBC(Subband Codec)·AAC(Advanced Audio Coding)·SSC UHQ(Samsung Seamless Codec)·LC3 중 저비트레이트 압축 1등 = LC3
  • LC3 = '요즘 블루투스 소리 표준(LE Audio〔Low Energy Audio〕)'의 기본 압축기 (블루투스가 이어폰에 소리 보내는 새 방식) → 칩에 이미 내장, 추가 비용 0
  • 버즈엔 이미 LC3 압축기·해제기가 둘 다 있다 — 통화 땐 마이크 소리를 압축(comp)해 폰에 보내고(업링크), 음악 땐 폰이 준 LC3를 풀어서(decomp) 재생(다운링크). 그래서 '내 발화(압축)'도 '듣던 소리(해제)'도 추가 부품 없이 같은 LC3로.
  • 재압축 0: 이미 LC3로 온 내부음은 그대로 저장
  • SSC UHQ=고음질·갤럭시 전용 / SBC·AAC=효율 열위 / Opus=미지원

4 압축 원리 — "들리는 것만"

  1. 시간 → 주파수로 바꿔 본다: 출렁이는 파형을 "어떤 음높이가 얼마나 섞였나"로 바꿔 보는데, 소리는 음높이들의 합이라 이렇게 보면 다루기 훨씬 쉽다.
  2. 안 들리는 소리는 버린다: 큰 소리 옆 작은 소리나 사람이 둔감한 너무 높고 낮은 음처럼, 어차피 귀에 안 들리는 성분은 통째로 버린다.
  3. 중요한 곳에 비트를 몰아준다: 잘 들리는 주파수는 촘촘하게, 덜 중요한 곳은 듬성듬성 표현해 데이터를 중요한 데 집중시킨다.
  4. 남은 걸 한 번 더 짠다: 남은 숫자들 중 자주 나오는 값에 짧은 코드를 붙여 한 번 더 압축한다.

→ 귀엔 거의 똑같은데 데이터는 1/30

🎧 왜 24kbps면 충분?  Spotify '데이터 절약'·📻 디지털 라디오·📞 HD 통화가 딱 이 수준 — 무슨 곡·무슨 말인지 알아듣기 충분. 우리 목적은 '감상'이 아니라 '식별·이해' → 더 높이면 용량 낭비, 더 낮추면 식별 불안. 24kbps = sweet spot.

S05 · 발화 끝 감지

말이 끝난 걸 버즈가 어떻게 알까? — VAD

버즈4 프로는 이미 '내가 말하는 순간'을 안다 — 소리가 아니라 턱뼈 진동을 보기에, 같은 센서로 '말의 끝'을 정확히 잡는다.

1 "Voice Detect" — 버즈4 프로의 기존 기능

  • 음악 듣는 중 말을 시작하면 자동으로 음악 볼륨↓ + 주변음 모드 → 상대 말이 잘 들림.
  • 말을 멈추고 일정 시간(5·10·15초 설정) 뒤 자동 원복.
  • 양쪽 버즈 모두 착용 시 동작 · Galaxy Wearable 앱에서 켬.
  • → "착용자가 말하는 중인지" 감지를 이미 양산 중 (새 기술 아님).

2 기술 — VPU(Voice Pickup Unit) 골전도 감지

  • 버즈4 프로 센서 = 가속도계·자이로·홀·근접·터치 + VPU. Voice Detect는 양쪽 버즈의 이 VPU(음성 감지 센서)로 발화를 잡는다.
  • VPU = 단일축 압전(piezoelectric) 보이스 가속도계 — 공기로 오는 소리가 아니라, 말할 때 턱·두개골을 타고 오는 골전도 진동을 전기신호로 변환.
  • 골전도 신호라 주변 소음(공기 전파)에 면역 → 착용자 목소리만 픽업. (마이크 '소리'가 아니라 '진동'을 봄)

3 BudsAI는 어디에 쓰나 — '말 끝' 감지

  • 버즈4 프로: 말하면 → 주변음 모드 전환에 사용.
  • BudsAI: 트리거 후 녹음하다가 그 센서로 '말이 끝났다'를 감지해 자동 종료.
  • '끝' 버튼 불필요 — 침묵 800ms면 종료.

4 왜 이 방식이 딱인가

  • 녹음 중에도 이어폰엔 음악이 나오고 주변은 시끄러울 수 있다.
  • 소리만 보는 방식은 "아직 말하는 중"으로 착각 → 안 끊김.
  • 턱 진동만 보는 가속도계는 면역 → 말 끝을 정확히.

BLUETOOTH · SBAP
S06 · 갤럭시 폰과의 통신

버즈는 폰에 뭘 어떻게 보낼까? — Bluetooth·SBAP

버즈와 폰은 보이지 않는 2.4GHz 전파로 대화한다 — 그 봉투 안에 세 소리와 호출 명령을 한 번에 묶는 삼성만의 규약(SBAP)을 싣는다.

1 전파를 어떻게 내보내나

  • RF(무선주파수) 트랜시버(칩 내장) + 안테나 → 2.4GHz 전파
  • 초당 ~1600번 채널 바꿔 뜀(호핑) → 간섭·도청 회피
  • 센트럴(폰)↔페리페럴(버즈), 페어링 후 AES 암호화
  • 기기마다 고유 주소 MAC = BD_ADDR

2 블루투스 패킷에 담기는 것

  • 주소(누구→누구) · 패킷 타입
  • 순서번호 + 수신확인(ACK, Acknowledgement) · 오류검출(CRC, Cyclic Redundancy Check)
  • 페이로드 ← 여기 안에 우리 삼성 내부 패킷

📦 한 줄 정리

버즈는 호출 명령 + 3스트림만 한 봉투(SBAP)에 담아 보내고, 무슨 의도인지·어떻게 처리할지는 전부 서버가 판단.

  • 따로 안 보냄, 한 메시지에 묶어 한 번에 · 메타의 '위치/길이'로 잘라 구분
  • 세션ID = 이 요청 한 건의 '이름표'. 메시지가 커서 BT로 보낼 땐 작은 조각으로 쪼개지는데, 모든 조각이 같은 세션ID → 받는 쪽이 모아 한 메시지로 재조립. (서버 응답도 같은 세션ID로 짝 · 후속은 '이전 세션ID'로 연결 · 3스트림은 애초에 한 메시지)
  • 의도 분류는 100% 서버 — 버즈는 "호출 + 들어있는 스트림"만 보냄
4 왜 자체 포맷(SBAP)이 필요한가 — 사설이라 좋은 게 아니라, 표준에 그릇이 없어서
  • 멀티스트림+명령 컨테이너 (핵심) — 표준 오디오 프로파일(A2DP=재생 1스트림·HFP=통화)엔 "내부·외부·발화 + 호출 명령"을 한 번에 담을 그릇이 없음 → 자체 페이로드 포맷이 필수.
  • 1st-party 스키마 자유 진화 — 버즈·폰·서버가 전부 삼성이라 필드를 자유롭게 정의·추가하고 빠르게 바꿈(SIG 표준화 불필요). 비밀이라서가 아니라 3자 모두 1st-party라서.
  • LC3 재압축 0 — 이미 LC3인 내부음은 디코드·재인코딩 없이 프레임 그대로 실어 운반.
  • 표준 위에 얹는 보안 — 봉인은 표준 mTLS, 무결성은 서명/CRC가 담당. SBAP는 그걸 '실어 나르는 컨테이너'일 뿐(프로토콜이 비밀이라 안전한 게 아님).

※ 순서·무손실은 전송(mTLS/TCP)이, 보안은 표준 암호가 보장 — SBAP 고유 공이 아님. 경쟁 해자도 와이어 포맷 비밀이 아니라 HW·실리콘·모델·UX 통합에서 나온다.

비싼 AI 서버에 가짜·루팅폰·짝퉁 버즈가 몰리면 비용도 보안도 무너진다 — '정품 폰'과 '정품 버즈'만 각자 다른 방식으로 증명해 들인다.

📱 폰 = Knox Attestation — "진짜 정품 갤럭시 + 변조/루팅 안 됨"을 하드웨어로 증명 (앱+OS엔 mTLS보다 이게 정석)

무엇을 증명 · 하드웨어 뿌리
  • ① 진짜 정품 삼성 갤럭시  ② 부팅·OS가 변조/루팅 안 됨
  • 신뢰가 공장 제조 시점부터 시작 · 기기마다 고유 하드웨어 키
  • Attestation Key를 Knox Vault(변조방지 금고)에 봉인 · 전송은 TLS
검사 항목 (Device Health)
  • Trusted Boot — 부트로더→커널 각 단계가 정품 서명인지 측정·검증 · 부트로더 잠김(OEM unlock off) 확인
  • Knox Warranty Bit — 언락·루팅·커스텀 바이너리 플래시 시 e-fuse가 0→1 영구(복구 불가). 트립되면 삼성페이·보안폴더도 영구 차단 → '손댄 기기' 영구 식별
  • 주기적 커널 측정(PKM) — 부팅 후에도 런타임으로 커널 코드·핵심 데이터 해시를 측정 → 루트킷·런타임 변조 탐지 (RKP가 커널 실시간 보호)
검증 흐름 (nonce 챌린지-응답)
  1. (우리)서버가 nonce(1회용 난수) 생성 → 앱에 전달
  2. 앱이 기기 Knox Attestation API 호출(nonce 전달)
  3. 기기가 검사 결과(부트·루팅·커널·기기 식별)를 모아 Knox Vault의 Attestation Key로 서명(nonce 포함)
  4. Samsung Attestation 서버가 Attestation Key 인증서 체인(삼성 루트까지)·nonce 일치·서명·기기 상태 검증 → verdict(정품·무결성) 발급
  5. (우리)서버가 verdict로 통과/거부 · nonce로 리플레이 차단 · 전송 TLS

🎧 버즈 = mTLS

버즈는 mTLS 디바이스 인증서로 "정품 갤럭시 버즈"임을 증명. (다음 장 S08)

  • Knox Attestation은 버즈엔 안 됨 — Knox OS가 없는 작은 펌웨어라서. 그래서 mTLS로.
  • 버즈는 앱스토어·OS 수정이 없어 '루팅' 개념이 거의 없음 → 인증서면 충분.
  • 펌웨어 무결성은 SoC 시큐어 부트가 담당 (S09)

버즈는 어떻게 '진짜'임을 증명할까? — mTLS

보통 TLS는 손님만 서버를 확인하지만, mTLS는 서버도 "너 진짜 버즈야?"를 묻는다 — 태어날 때 받은 신분증으로 서명 2번·검증 2번.

🔒 mTLS = 양방향 TLS — 일반 TLS는 서버만 인증서로 "진짜 서버?" 확인, mTLS는 버즈도 인증서 제시해 서로 검증 🖋️ 신원 증명 = 디지털 서명 — 개인키로 '도장(서명)' → 짝인 공개키로만 검증(키는 안 드러남)

🌱 Phase 0 · CA 준비 출시 전 · 딱 한 번

  1. 삼성이 CA(인증 기관) 설립 → CA 키쌍 생성:
    · CA 개인키 — 극비(본사 HSM 금고), 인증서에 도장 찍는 용도
    · CA 공개키 — 그 도장을 검증하는 열쇠
  2. CA 공개키를 서버에 미리 심음 = 신뢰의 뿌리 (서버가 처음부터 가진 단 하나)
→ 모든 버즈의 '보증인'이 준비됨

🏭 Phase 1 · 제조 버즈마다 · 공장

  1. 공장이 칩에 "키쌍 만들어" → 칩이 버즈 키쌍 생성:
    · 🔑 버즈 개인키 — 칩 금고 봉인, 영영 안 나옴
    · 🔓 버즈 공개키 — 꺼낼 수 있음
  2. 칩이 [버즈 공개키 + 기기ID #ABC123]를 공장 서버로 내보냄
  3. ✍️ CA가 'CA 개인키'로 서명 → 📜 인증서 발급
    인증서 ≈ {기기ID, 버즈 공개키, 유효기간} + CA 서명 = "이 공개키 = 진짜 정품 버즈 #ABC123" 보증
  4. 인증서를 버즈 칩에 저장(개인키 옆) → 출고
📦 버즈 안 = 개인키(봉인) + 인증서(공개키+CA도장)

🔌 Phase 2 · 접속 접속마다 · mTLS

  1. 서버 → 버즈: "인증서 줘 + 이 랜덤값에 서명해" (매번 다른 챌린지)
  2. 버즈 → 서버: ① 📜 인증서(공개키+CA도장) + ② ✍️ 챌린지 서명(버즈 개인키로)
  3. 🔍 검증 A · 인증서 검증 — 서버의 CA 공개키로 인증서의 CA 도장 확인 → 이 공개키 = 진짜 정품 버즈 거 ✅
  4. 🔍 검증 B · 소유 증명 — 인증서 속 버즈 공개키로 챌린지 서명 검증 → 개인키도 보유 = 도용 아님 ✅
  5. 둘 다 통과 → 정품 버즈 확정 · 접속 허용 🎉
✍️ 서명 2번 — 제조 시 CA가 인증서에 · 접속 시 버즈가 챌린지에   |   🔍 검증 2번 — (A) CA공개키로 인증서 진위 · (B) 버즈공개키로 개인키 보유
PKI(Public Key Infrastructure) · CA(Certificate Authority, 인증 기관) · 인증서 ≈ {기기ID·버즈 공개키·유효기간} + CA 서명

S10 · 보안 ③ 키 보관

그 비밀 키, 어디에 숨기지? — 보안 SoC

가장 약한 곳은 '보관'이다 — 키를 코드에 두면 칩을 뜯는 순간 통째로 털린다. 그래서 칩 속 금고에 넣고 '쓰기만, 꺼내기는 아예 없게' 잠근다.

1 키를 어디에 두나

키를 펌웨어(코드)에 넣으면 칩을 뜯어 덤프하는 순간 털린다. 그래서 코드가 아니라 보안 SoC(System on a Chip)의 하드웨어 금고에 잠근다.

→ 그 금고의 본체가 KMU, 금고를 우회 못 하게 나머지 3겹이 감싼다.

2 금고 본체 = KMU (Key Management Unit, 키 관리 유닛)

키로 '서명·암호 연산'만 대신 해주고, 키를 꺼내는 명령은 아예 없다(읽기 경로 자체가 없는 HW). 펌웨어는 슬롯 번호로만 부탁 → 결과만 받음.

펌웨어 ─"키 #3으로 이 값 서명해줘"─▶ [KMU 금고 🔐]
펌웨어 ◀──────"서명 결과만"──────  ✅ 결과는 줌  /  ❌ 키는 절대 안 줌

🥤 자판기처럼 — 음료(결과)는 받아도 안의 현금통(키)은 못 꺼낸다.

3 KMU 혼자선 불완전 — 공격은 '정상 경로'로만 오지 않는다 → 나머지 3겹이 우회로를 막는다

🔐 시큐어 부트 ★ KMU와 한 쌍
막는 구멍 — 변조·악성 펌웨어가 실행되면

그놈이 합법적으로 "키 #3으로 서명해줘"를 시킬 수 있다 → ROM 루트키로 검증해 정품 서명 펌웨어만 부팅시켜 차단. 이게 뚫리면 KMU의 '쓰기 허용'이 공격자에게 열린다.

🧱 TrustZone
막는 구멍 — 일반 코드가 키 영역을 엿봄·건드림

일반 세계 코드가 KMU·키 연산 영역을 들여다보거나 건드리지 못하게, CPU가 보안/일반 세계를 물리적으로 분리.

🎲 온칩 생성 · 디버그 잠금
막는 구멍 — 우회로로 키를 빼냄

키를 칩 내부 난수(TRNG)로 생성(밖에 안 나옴)·루트비밀 OTP에 굽고, JTAG/SWD 포트를 잠가 메모리 덤프·프로빙 우회 추출을 차단.

🔑 KMU = 금고 본체(키를 못 꺼내게) · 나머지 셋 = 우회·무력화를 막는 자물쇠·벽·경비. 특히 시큐어 부트가 무너지면 KMU 보호가 통째로 의미를 잃어 → "핵심은 KMU"지만 실제 안전은 시큐어 부트 + KMU 한 쌍이 받친다. 별도 보안칩 없이 SoC 기능만 켜면 됨(추가 칩 0).
4 그래서 얻는 것 — '정품 버즈만 접속 + 현장에 키 평문 0'이 만드는 실제 효과
🤖 봇·어뷰징·도용 차단
인증서 없으면 TLS 핸드셰이크 단계에서 거절 → 가짜 폰·복제 앱·짝퉁 버즈가 비싼 STT·LLM 추론을 한 번도 못 돌림(GPU 비용 0).
📊 기기별 식별·과금
인증서의 위조 불가 고유 ID로 기기별 사용량 집계·요금·속도 제한·이상탐지 → 폭주하는 한 대만 콕 집어 차단.
🗄️ 털려도 안전한 서버
서버엔 비번·대칭키 DB가 없고 공개키만 보관 → DB가 통째로 유출돼도 위조 접속 불가(훔칠 비밀이 없음).
