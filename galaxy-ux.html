07 · GALAXY UX

Galaxy + Buds 특화 UX

Galaxy 폰 사용자에게만 제공되는 추가 레이어. Dumb bridge 위에 얹어 호환성은 유지하면서 갤럭시 생태계만의 가치를 더한다.

아키텍처적 위치 이 모든 기능은 범용 호스트 브릿지를 끄거나 대체하지 않습니다. Bridge는 그대로 작동하고, 그 위에 Galaxy 전용 컴패니언 앱이 관찰자(observer)로 얹혀 부가 가치를 만듭니다. 타사 기기 호환성은 변하지 않습니다.

1. 왜 Galaxy 특화인가

  • 이미 가지고 있는 자산: Galaxy Wearable, SmartThings, One UI, Bixby 등 생태계 인프라 재사용
  • 제조사 차별화: "삼성을 쓰면 BudsAI가 더 똑똑하게 동작" — Galaxy 구매 이유 강화
  • UX 끝맺음: 답변을 음성으로만 듣는 것 외에 시각적/지속적 액세스 제공
  • 플랫폼 통합: 락스크린, 노티, Always-On Display까지 자연스러운 연결

2. 아키텍처 레이어링

┌──────────────────────────────────────────────────────────────┐ │ Galaxy Companion App (One UI 내장 또는 Galaxy Wearable 내) │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ │ │ 히스토리 │ │ 설정 │ │ Bixby │ │ SmartTh. │ ← Galaxy 전용 │ │ 타임라인 │ │ 위젯 │ │ 라우팅 │ │ 연동 │ │ └──────────┘ └──────────┘ └──────────┘ └──────────┘ │ └────────────────────┬─────────────────────────────────────────┘ │ (서버에 read API, push 구독) │ ─────────────────────┼─────────────────────────────── 표준 레이어 ─── │ ┌────────────────────▼─────────────────────────────────────────┐ │ BudsBridge / OS BT PAN (어떤 호스트에서든 동작) │ │ - BT ↔ TCP 바이트 파이프, AI 모름 │ └──────────────────────────────────────────────────────────────┘ ▲ ▲ │ BT (암호문) │ HTTPS (암호문) │ │ [Buds] ──────── E2E TLS ──────────────────── [Server]

Galaxy 앱은 BT 경로에 끼어들지 않는다. 서버 측 read API를 통해 자기 계정의 히스토리/상태를 읽어와 UI를 만든다.

3. Galaxy가 데이터를 얻는 경로

3.1 Pull (서버 조회)

Galaxy 컴패니언 앱이 자기 계정으로 서버 API에 인증해 히스토리/세션 결과를 조회.

  • GET /v1/sessions?after=…&limit=20 — 최근 세션 목록
  • GET /v1/sessions/{id} — 특정 세션 상세 (텍스트/오디오 URL)

3.2 Push (실시간 알림)

새 세션 완료 시 서버가 Galaxy 컴패니언 앱에 푸시.

  • FCM/HMS 푸시 + 데이터 페이로드
  • 오디오 답변이 끝나는 시점 즈음에 폰 화면에 "방금 답변" 카드 표시

3.3 Audio Snoop (선택, 권한 후 활성)

Galaxy Wearable에 기본 페어링된 버즈는 SCMS-T 보호 외에 별도 보조 채널로 세션 메타데이터를 함께 보낼 수 있음 — 사용자가 명시적으로 동의 시:

  • 버즈가 응답 직후 GATT 별도 characteristic으로 "세션 ID + intent + 텍스트" 짧게 전송
  • Galaxy 앱이 즉시 카드/노티 표시 (서버 푸시보다 빠름)
  • 여전히 페이로드 본문은 E2E TLS로 안 보임 — 메타만 공유
주의 Audio Snoop은 사용자 동의 + Galaxy 환경 자동 감지 시에만 활성. 타사 폰에서는 0.

4. 특화 기능 목록

🕒 타임라인 히스토리

오늘 들은 곡, 번역한 문장, 요약한 강의를 시간순으로. One UI 디자인.

🔍 검색

"지난주 영어 단어 뭐였지?" 자연어로 히스토리 검색.

📌 핀 / 즐겨찾기

좋아한 곡, 외울 단어, 다시 들을 답변을 저장.

📲 위젯

홈 화면 위젯에 "최근 답변" 표시, 락스크린 위젯 지원.

🌗 Always-On Display

답변 핵심 한 줄을 AOD에 잠시 표시 (옵션).

🎵 Spotify/YouTube Music 딥링크

곡 식별 결과 → "이 곡 재생" 버튼 한 번.

📚 단어장

번역/사전 검색한 단어를 자동 단어장으로 → Galaxy Notes/Quizlet 연동.

📝 회의 노트

회의 통화 중 트리거 → 답변 + 원문을 Samsung Notes에 자동 저장.

🌍 Galaxy AI 통합

One UI의 Galaxy AI 번역/요약 기능과 같은 보이스 톤·언어 설정 공유.

🤖 Bixby 라우팅

오디오 무관한 일반 질문은 Bixby로 라우팅 옵션.

⌚ Galaxy Watch 뷰

워치 화면에 최근 답변, 트리거 횟수, 빠른 재생.

🏠 SmartThings 자동화

"이 곡이 식별되면 거실 조명 무드 모드로" 같은 루틴.

5. Galaxy Wearable 통합

BudsAI 설정 UI는 별도 앱이 아니라 Galaxy Wearable 앱 안의 한 섹션으로 들어감.

5.1 Wearable 내 진입 경로

Galaxy Wearable 앱 ├── 내 버즈 │ ├── 노이즈 컨트롤 │ ├── 터치 컨트롤 │ ├── 이퀄라이저 │ └── BudsAI ← 여기 진입 │ ├── 활성화 / 트리거 제스처 │ ├── 버퍼 길이 │ ├── 응답 언어/음성 │ ├── 히스토리 (Galaxy 전용) │ ├── 단어장 (Galaxy 전용) │ └── 프라이버시

5.2 펌웨어 OTA

  • 버즈 펌웨어 업데이트가 Galaxy Wearable 안에서 같이 관리됨
  • BudsAI 펌웨어 모듈은 별도 채널 (slow/stable) 선택 가능

6. Bixby 라우팅 옵션

6.1 동작

사용자가 트리거 후 "오늘 날씨 어때?" 같이 청취 오디오와 무관한 질문을 하면:

  1. 서버 의도 분류가 general로 분류
  2. (Galaxy 환경 + 사용자 옵션 ON) 시 답변을 Bixby에 위임 가능
  3. Bixby가 답을 만들어 BudsAI 서버로 회신
  4. BudsAI는 그대로 TTS로 버즈에 전달

6.2 왜 옵션인가

  • Galaxy 사용자라도 BudsAI 자체 LLM을 선호할 수 있음
  • 또는 Galaxy 디바이스 명령("이 사진 보내줘") 같은 건 Bixby가 더 잘함 → 자동 라우팅 가치

7. SmartThings / Find 연동

7.1 SmartThings Routines

BudsAI 세션 결과를 트리거로 사용:

If (BudsAI.intent == "song_id") AND (BudsAI.result.genre == "jazz") then
    SmartThings.Routine("저녁 재즈 무드"): 거실 조명 dim, 스피커 볼륨 ↓

7.2 SmartThings Find

  • 버즈 분실 시 Galaxy Find로 위치 추적 (기존 기능)
  • BudsAI는 별도 영향 없음

8. 멀티 디바이스 핸드오프

Galaxy 생태계 안에서는 한 사용자가 폰/태블릿/워치/PC를 동시 보유. BudsAI도 이 사이를 매끄럽게 이동.

8.1 시나리오

상황: 폰으로 음악 듣다가 폰 두고 산책 가면서 Galaxy Watch만 차고 나감

동작:

  1. 버즈가 폰 BT 끊기는 걸 감지
  2. Galaxy Watch에 자동 재연결 (이미 페어링됨)
  3. Watch가 LTE/Wi-Fi로 호스트 브릿지 역할 수행
  4. 사용자 입장: 끊김 없이 그대로 BudsAI 사용

8.2 동시 다중 페어링

  • Galaxy 디바이스는 Multipoint BT로 폰+태블릿 동시 연결 지원
  • 현재 활성 디바이스의 호스트 브릿지를 사용, 다른 디바이스는 idle
  • 전환 시 서버 세션은 그대로 유지 (디바이스 인증서가 같으므로)

9. 프라이버시 분리

  • 오디오 페이로드: Galaxy 앱조차 못 봄 (E2E 유지)
  • 메타데이터(히스토리/intent): 사용자 동의 후 Galaxy 앱이 서버에서 읽음
  • 로컬 저장: Galaxy 앱이 히스토리 캐시를 폰에 저장하지만 Knox 보안 영역 사용
  • 옵트아웃: 사용자가 Galaxy 특화 기능을 끄면 즉시 캐시 삭제, 푸시 구독 해지
  • 비 Galaxy 사용자: 영향 0 — 페이지조차 보지 못함
